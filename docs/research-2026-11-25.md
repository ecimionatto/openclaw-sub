**Theme:** clawsub · openclaw-native-cli-runtime: patch `openclaw.json` natively and bundle the `openclaw-agy-cli` plugin

**Why it matters**
• `clawsub` v0.2.0 generates standalone shell shims (`~/.openclaw/bin/clawsub-*`), but OpenClaw 2026.11+ actually routes CLI models natively through `~/.openclaw/openclaw.json` using `agentRuntime: { id: "claude-cli" | "agy-cli" | "codex" }`.
• Furthermore, OpenClaw ships built-in plugins for `claude-cli` and `codex`, while Google Antigravity (`agy`) requires the `@local/openclaw-agy-cli` plugin (`definePluginEntry` + `api.registerCliBackend`) with `--dangerously-skip-permissions --disable-slash-commands --settings '{"allowNonWorkspaceAccess":true}' --output-format stream-json`.
• Without bundling `@local/openclaw-agy-cli` and patching `openclaw.json`, a new user running `clawsub init` still has to manually edit `~/.openclaw/openclaw.json` to get native session resumption (`--conversation {sessionId}`) and stream-json tool events.

**Findings**
• OpenClaw's plugin SDK (`openclaw/plugin-sdk/plugin-entry`) lets a local plugin register a first-class CLI backend via `api.registerCliBackend({ id, modelProvider, parseJsonlEvent, config })` with native `sessionMode: "existing"` and JSONL streaming [1].
• Disabling `sessionCatalog` (`plugins.entries.anthropic.config.sessionCatalog.enabled = false` and `plugins.entries.codex.config.sessionCatalog.enabled = false`) prevents OpenClaw from requiring raw API keys when using `claude-cli` and `codex` runtimes [2].
• Antigravity CLI (`agy`) blocks headless turns on out-of-workspace file access unless launched with `--dangerously-skip-permissions --disable-slash-commands --settings '{"allowNonWorkspaceAccess":true}' --output-format stream-json` [3].
• In today's cron diagnostics (`openclaw cron get`), when `claude-opus-5-5` hit its weekly limit (`resets 11pm`) and `agy-cli` hit an auth timeout, OpenClaw reported the exact command needed to re-authenticate: `openclaw models auth login --provider 'agy-cli' --force` [4].
